# 任务台 v1 · 设计说明

> 可点设计稿：\`design/app-redesign/index.html\`（含同目录 \`styles.css\`、\`app.js\`）。
> **只做设计，没有改动任何 Kotlin 代码**。

## 1. 一句话

把「8 张长得一样的任务卡 + 藏在第三个页面里的进度」改成 **一张任务台**：顶部一条常驻汇总条回答「上次跑到哪」，2×2 四象限让 8 个业务一眼可辨，任务启动后**卡片原位长成跑道**，不用离开首屏。

## 2. 为什么是这个方向

| 方向 | 形态 | 为什么没选 |
| --- | --- | --- |
| A 控制台 | 左侧任务清单 + 进度轨道 + 日志流常驻 | 把「监控」当主任务。用户一天切 2–5 次业务，大多数时间不是在跑任务，常驻日志流让首屏一半是空的 |
| **B 任务台（采用）** | 汇总条 + 2×2 业务卡 + 右侧抽屉 + 卡内跑道 | 首屏核心动作是**认出该点哪个业务**，B 把它放在第一视觉层；同时把 A 的常驻进度吸收进汇总条 |
| C 三步引导 | 无导航、大标题 + 三步、运行时全屏进度 | 引导只对第一次有用；第 20 次打开时它挡在业务前面，切换成本最高 |

判断依据是三个问题（打开后 5 秒内）：**该点哪个任务 / 上次跑到哪 / 现在能不能接着跑**。

## 3. 结构上改了什么

| 现状（代码里） | 设计稿 | 解决哪个问题 |
| --- | --- | --- |
| \`TaskMode.kt:398\` 8 张 \`Adaptive(320.dp)\` 卡，同款同权重，无历史信息 | 2×2 四象限，按 4 个业务域分组；每卡第三行「上次 3 月 12 日 · 131 条」+ 状态词（未录入用红、全部成功用灰粗体） | 该点哪个 |
| 进度/日志在独立「任务执行」页（\`TaskExecute.kt:173\`），要点底栏圆环徽标才看到 | 汇总条常驻 + 卡片原位展开为跑道（已录入条数、当前行、最近日志、失败明细） | 上次跑到哪 |
| 启动是居中 \`Dialog\`，遮住卡片、打断视线 | 右侧 440px 抽屉滑入，左侧卡片上下文保留 | 该点哪个 |
| 左侧 \`NavigationRail\` 占宽、只有「任务模式/设置」两项 | 顶栏右侧分段控件，宽度还给内容 | 信息密度 |
| 底栏圆环进度徽标 | 顶栏 \`runpill\`（任务名 + 迷你进度条，**不写数字**） | 跨页面可见，且不与汇总条的数字打架 |
| 失败只在日志里有一行 | 失败明细表（行号 / 姓名 / 原因）+「导出失败明细」+ 汇总条主按钮「重试这 3 条」 | 现在能不能接着跑 |
| \`TaskHistory.kt:16\` 占位页 | 历史并入每张卡的上次运行摘要与汇总条，不再单开一页 | 少一层导航 |
| 只有浅色主题、单一主色 | 暖白 + 医疗蓝 + 4 个业务域色（组头 3px 竖条 + 图标 tint，**不是卡片左色条**） | 该点哪个 |

保留不动的：任务仍是串行（运行时其余 7 张卡降到 62% 不透明度并禁用，页头改成「本轮进行中 · 其他 7 个任务在本轮结束后可启动」）、账号仍是 4 组共用、启动仍需 Excel + 账号密码三样。

## 4. 视觉规格

**色板**（\`:root\` 里可直接取）

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| \`--bg\` | \`#FBFAF8\` | 页面底（暖白，长时间看不发灰） |
| \`--surface\` / \`--surface-2\` / \`--surface-3\` | \`#FFFFFF\` / \`#F5F2ED\` / \`#EDE9E1\` | 卡片 / 次级块 / 进度槽 |
| \`--ink\` / \`--ink-2\` / \`--ink-3\` | \`#171A1F\` / \`#4B525D\` / \`#6B7280\` | 标题 / 正文 / 辅助 |
| \`--line\` / \`--line-2\` | \`#E7E2D9\` / \`#D8D2C6\` | 常态分隔 / 输入框描边 |
| \`--brand\` / \`--brand-deep\` / \`--brand-tint\` | \`#1857D6\` / \`#123F9E\` / \`#EDF2FE\` | 主操作、进度、选中 |
| \`--ok\` / \`--warn\` / \`--err\` | \`#17703C\` / \`#8A5A00\` / \`#BE3327\` | 成功 / 未录入 / 失败（文字色均已压到 4.5:1 以上） |
| 业务域色 | 血压 \`#D93A3A\` · 血糖 \`#D98324\` · 体检 \`#1F8A4C\` · 签约 \`#5B5BD6\` | 只用于组头 3px 竖条与图标 tint |

**字**：系统中文无衬线（微软雅黑 UI / 苹方 / 思源黑），路径与日志用等宽。字号角色 \`20 / 15 / 14 / 13 / 12.5\`，正文 13–14px、行高 1.5–1.75，没有 10px 一类的「精致小字」。

**形**：圆角 6 / 8 / 10 / 14；间距 24 / 16 / 14 / 12；三层阴影（1px 常态、8px 悬停、18px 抽屉）。图标单套 24 网格、1.75 描边，全部内联 SVG，不引图标字体或 CDN。

## 5. 动效（只做三处）

1. **主操作反馈**：按钮按下 \`scale(.97)\` 80ms；卡片悬停上浮 1px + 阴影 160ms；卡片右侧箭头在悬停时才淡入。
2. **状态切换的来路**：抽屉 280ms 从右侧 28px 滑入（遮罩 180ms 淡入到 28% 黑）；卡片长成跑道时面板 240ms 上浮 8px 淡入；完成态的勾 340ms 描边画出（\`stroke-dashoffset\`）。
3. **首次进入依次出场**：页头 → 汇总条 → 四象限，间隔 60ms，各项 320ms，总计约 500ms。

\`prefers-reduced-motion: reduce\` 时全部降到 0.001s。**没做**：滚动视差、悬浮粒子、数字滚动。

## 6. 收敛掉的多余东西

- 侧栏「自动助手」标题（品牌名已在顶栏）、导航词「任务模式 / 任务执行」（「任务执行」不是目的地，而是某张卡的状态）。
- 空态文案「任务开始后日志会显示在这里」→ 直接给「正在处理 第 129 行 · 王秀兰」。
- 启动表单的必填校验提示（按钮置灰即可）；账号行的「已保存」小标签（下一行已说明）。
- 设置页的 4 个 \`OutlinedCard\` 容器（改成 hairline 分区）、「目标系统」下的地址说明。
- 卡片右侧箭头常显（8 个一样的按钮是噪音，改悬停出现）、日志与失败明细的外层卡片边框（卡片套卡片）。
- 运行态里重复的「共 131 条 · 已用 12:38」（汇总条已有）、完成态卡片副标题（跑道里已有）、失败态卡片的第二个主按钮（主操作只在汇总条出现一次）。

## 7. 没做什么（边界）

- **没改任何 Kotlin 代码**（用户明确「只设计不要实现」）。
- 没做深色主题；没做多任务并发；没做完整键盘流程（只留 \`focus-visible\` 环与 Esc 关闭）；没做 i18n。
- 抽屉里的文件、账号、日志、失败行都是静态示例数据，没有接文件选择器与真实进度流。

## 8. 怎么看

打开 \`design/app-redesign/index.html\`，每个状态一个 URL：

\`?state=idle\` 任务台 · \`drawer\` 启动抽屉 · \`running\` 运行中 · \`done\` 完成 · \`failed\` 3 条失败 · \`settings\` 设置

点卡片开抽屉 → 「启动任务」进运行态 → 汇总条「取消任务」回任务台；「查看失败记录」直接到失败态。

## 9. 评审

两位**没有看过设计过程**的独立评审（各自只看截图与源码）分别给 **7/10** 与 **7.5/10**，共同结论：任务台这个组织方式成立，扣分集中在「窄窗同屏比较」和「进度口径不一致」。按评审意见改了 8 处：

| # | 评审指出 | 改法 |
| --- | --- | --- |
| 1 | 960×640 退成单列，首屏只剩 4 张卡 | 断点 \`1100px → 900px\`（\`styles.css\` 媒体查询）。960 仍是双列，四组八个任务全部同屏 |
| 2 | 进度三处数字互相矛盾（顶栏 128/131、汇总条 129/131、卡内 128/131 与 97.7%） | 一屏只出现一次：顶栏胶囊只留**迷你进度条**，汇总条只讲**当前第几行**，卡内只讲**已录入 128 / 131 条**，百分比只在汇总条进度块 |
| 3 | 运行/失败态卡片长高把最后一行顶出视口 | 删掉与汇总条重复的副标题、日志压到 3 行（只留信息量最高的尾部三行，含失败行）、「展开完整日志」移到卡片头部。1280×800 下第四组两张卡回到屏内 |
| 4 | 汇总条按钮答非所问（idle「再跑一次」指代不明、failed 主操作是「返回任务台」） | idle 主按钮 = **补齐这 3 条**；failed 主按钮 = **重试这 3 条**（实心），「返回任务台」降为 ghost；文案统一「可只补录这 3 条，不必重跑全部」 |
| 5 | 组头域色圆点与失败红点同形同色，分不开 | 组头改成 **3px 竖条**（圆点只保留在失败行） |
| 6 | 禁用态只靠 \`opacity:.5\`，点击没反馈 | 提到 \`.62\`，并在页头写明「其他 7 个任务在本轮结束后可启动」 |
| 7 | 八张卡里的「3 条未录入」藏在灰字里，首屏不抢眼 | 状态词从 meta 里拆出来单独着色：未录入用 \`--err\` 粗体，全部成功用 \`--ink-3\` 粗体（成功不抢注意力，只有问题发红） |
| 8 | 失败明细/汇总条/卡片重复报同一个 128 | 每处只讲一件事：汇总条讲「128 条成功 · 可只补录这 3 条」，表头讲「3 条记录未录入」，脚注讲「成功的不会重复录入」 |

**有理据地没采纳的一条**：评审建议运行时把另外 7 张卡压成 48px 紧凑态以免跳动。没采纳——运行时其余任务本就禁用，压成紧凑态反而丢掉「上次跑到哪」这条信息；改为让跑道自身变矮（第 3 条），效果相同而信息不丢。

**已知风险**：Compose 没有 grid 的 \`column-span\`。若跑道用 \`animateContentSize()\`，卡片从约 88dp 长到约 200dp 会把下半象限整体顶下去，原型里「其它卡不动」在真实实现中会走样。落地时建议：跑道改用固定高度（约 200dp）并在 \`AnimatedContent\` 里做内容切换，而不是让容器自由撑高。

## 11. 落到 Compose 的映射（给以后实施）

- 顶栏 → \`Row\` + \`Surface\`；分段控件 → \`Row\` 包两个 \`Surface\`（Material3 无现成 \`SegmentedButton\`）。
- 2×2 → 固定 8 项，用 \`Column { Row { ... } }\` 比 \`LazyVerticalGrid\` 更省滚动与状态；≤900dp 退化成单列。
- 卡片原位展开 → 同 key 的 \`AnimatedContent\` + 固定高度（见第 9 节风险）；不要依赖 \`animateContentSize\` 自然撑高。
- 汇总条换内容 → \`AnimatedContent\` 同槽位，高度固定（不能跳）。
- 抽屉 → \`AnimatedVisibility\` + \`slideInHorizontally\` + 自绘遮罩；\`ModalBottomSheet\` 是底部滑出，方向不对。
- 主题 → 替换 \`DynamicConfigTheme.kt:42\` 的 \`lightColorScheme\`：primary \`#1857D6\`、background \`#FBFAF8\`、surface \`#FFFFFF\`、surfaceVariant \`#F5F2ED\`、onSurfaceVariant \`#4B525D\`、outline \`#E7E2D9\`、error \`#BE3327\`。
- 图标 → \`material-icons-extended\` 里已有的 Favorite / WaterDrop / Assessment / Assignment / Handshake / Save；分层、归档、签名用现成近似或自制 vector。
- 字阶 → \`Typography\` 自定义：20/600、15/600、13/1.5、12.5/1.4。
